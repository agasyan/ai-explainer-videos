---
name: explainer-video
description: Make a narrated, animated explainer video about any topic, PR, repo, doc, recording, or HTML page (an internal docs page, a claude.ai artifact, any .html file), as a 9:16 story and/or 16:9 landscape MP4, in parts when long. Writes the script, renders a 720p video, and stops for the one approval check; 1080p is optional after it. Use when the user asks for an explainer video, an animated explanation, a video about a PR, repo, or HTML page, a reel or story explainer, or to continue a video in generated_videos/.
argument-hint: "<topic | PR | repo path | file | page.html | slug> [--format story|landscape|both] [--moodboard <name>] [--video-format <name>] [--plan-check] [--voice af_heart|am_michael|bf_emma|bm_george] [--length 60s]"
---

Each new video is a project: `projects/<YYYYMMDD>-<name>/`, made first, before any research, and every file of its work stays inside it. Videos made before projects stay in `generated_videos/<slug>/`; for those, use the slug as it is. One approval check: the 720p preview after step 2, which is the final video and covers the plan too. Do not stop after step 1. For an existing slug, run `make status SLUG=<slug>` and continue from there. To ask: show the summary, then run `make approve SLUG=<slug> STEP=preview`. Claude Code asks the user, and that answer is the approval. If the user declines, apply their change and ask again. If the command is denied without a message (headless run), stop and end with `WAITING FOR APPROVAL: <slug> preview`. Editing an approved file cancels its approval; say what changed when you ask again.

Plan check: with `--plan-check` (or "Plan check" in the request), stop after step 1 and ask with `make approve SLUG=<slug> STEP=plan` (headless: end with `WAITING FOR APPROVAL: <slug> plan`). Then go on to step 2.

Defaults: `landscape` (`story` if the user says IG, reel, story, phone, or TikTok), moodboard and video format recommended (step 1), voice `af_heart`, captions `pop`, viewer a smart colleague new to the topic, one video with no parts.

**Sub-agents, for speed.** At most 5 per step, all spawned in one message so they run in parallel; more items than 5 means 2 per agent. Sub-agents start blank, so paste in each one: the objective, input file paths, the rules it needs, its output shape, and a status of `DONE`, `DONE_WITH_CONCERNS`, or `BLOCKED` plus the reason. Sub-agents never run `make approve`, `make narrate`, `make preview`, `make video`, or `make from-html`, and never edit `script.yaml`, `style.css`, or `approved.json`. The main agent keeps the script, the style, the approvals, the full renders, and 1080p. Without sub-agents, do the same work yourself.

1. **Plan: script and storyboard.** Start the project: `make new SLUG=<kebab-name> TITLE="<title>"` (an HTML page: `make from-html`, below). When the request says `Slug: <id>`, the project id is fixed: use exactly that id in every command; else use the id `make new` prints. Keep what you read in the project, so it is complete on its own: readers and researchers write notes to `sources/<n>-<topic>.md` (facts with `path:line`, copied excerpts of the parts you use from a file, repo, diff, or doc outside this repo) and return a summary, and `sources/index.md` gets one line per source: what it is, and where it came from (path, repo and commit, PR, or URL). Read the source. For 5 or more files or sections, spawn reader sub-agents, one per group; each returns 15 or fewer facts, each with `path:line` or its section. Write the script yourself, in one voice. Topic: research first, with up to 5 researcher sub-agents, one per question group. Each opens every source it cites, takes each number and date from the page, and returns rows `| c<n> | claim | source 1 | source 2 | status |`; a claim needs two independent sources, else its status is `one source`. Write the rows to `research.md`, and give each beat that states a fact `sources: [c<n>]`. Then spawn one recommender sub-agent. Paste in the brief, the `research.md` path, `moodboards/catalog.json`, `video-formats/catalog.json`, and this rule: return the best video format and the best moodboard for this topic and viewer, plus 2 alternatives each, each with one line of why tied to the topic; pick a moodboard with `three: true` only for a spatial topic. Write its answer as `picks:` in `script.yaml` (the pick first) and set `video_format:` and `moodboard:` to the picks. A choice in the request (`Video format: x`, `Moodboard: y`) skips that catalog: set the field and leave its picks list empty. Set `three:` from the request (`3D: off` means `three: false`; else `true`). PR: `gh pr view <n> --json title,body,files` and `gh pr diff <n>`; tell it as problem, change, effect, risk. Repo: README, a depth-2 tree, entry points, 3 core files; tell it as purpose, main parts, one request through it, how to start. File: all of it. Recording: `make transcribe FILE=<path>`. Reference video: `make reference FILE=<path>`, then match its words and cuts per minute. Then replace every `(fill in)` in `script.yaml` and write each beat's `say` (narration) and `show` (what is on screen). Shape the scenes by the acts and beat ranges in `video-formats/<name>/format.md`, and give each scene a `treatment:` from `moodboards/<name>/moodboard.md`. A change request such as "use moodboard archival" sets the field, maps each treatment again, and runs narrate again. One beat is one visual change and 1 to 2 sentences. Make one video: aim for 60 s (140 words) for a story and 2 to 3 min (280 to 420 words) for landscape, and cover a long source by saying less about each part of it, not by splitting. Split into parts only when the request asks for a length per part (`--length 60s`, "Length per part: 2m"): then each part is that long or less and opens with one sentence of context. Write `say` about 80% of the way to ASD-STE100: 20 words or fewer per sentence, active voice, one word per meaning. Sentence one is the payoff; the last beat is the win plus one next action. Spell out what the voice reads ("two percent", "A P I"); code and URLs go in `show` only. Wrap 1 to 2 key words per beat in `*asterisks*`; the captions color them. Run `make narrate SLUG=<slug>` and fix until it prints no `CHECK` (voice, sources, picks, treatments). State only facts you read; list guesses in `brief.guesses`. Summary: `storyboard.md` (the picks, the video direction, one row per beat), the length per part, and `build/narration.wav`.
   **HTML page** (a source that is an `.html` or `.htm` file, or a page on an internal site): this starts the project in place of `make new`, and replaces the research and the recommender. For a page behind a sign-in, use a local copy or a connector's download; never work around the sign-in. Give `FILE=` an absolute path (resolve a relative one from the folder the user works in). Run `make from-html SLUG=<kebab-name> FILE=<path> [FORMAT=<f>]` and use the project id it prints; when the request says the page is copied already (dashboard), run `make from-html SLUG=<id>` with no `FILE=`. It copies the page and its CDN files, captures one scene per section, and drafts `script.yaml` (`treatment: page`, `say: (fill in)`) and `scenes/<id>.html`. Read `build/sections.json` (each section's heading, text, and parts) and, for detail, `assets/page/index.html`. Fill in the brief, then write each section's beats: delete a scene to skip its section, and give a long section 2 to 3 beats so the camera has time to scroll. State only what the page says. Then narrate as above.
2. **Preview: animation as code, 720p.** HTML page: the drafted scenes already show each section with a scrolling camera; add highlights only where a beat names a table, chart, or code block (`p.mark(p.parts[n], EV.at(beat, "word"))`, see `ev/web/page.js`), then run `make stills` and go to the full preview below; no scene sub-agents. Else write `style.css` yourself first: one color per concept and the shared classes, on top of the moodboard (scenes link `/ev/theme.css` after `base.css`, as the templates do). Then spawn one scene sub-agent per scene. Paste in each: its scene id, its `treatment`, and its beats (`id`, `say`, `show`), the path `moodboards/<name>/moodboard.md` (draw the treatment as its prose says), the paths `ev/web/ev.js` (API comment), `docs/scenes.md`, `style.css`, and `templates/video/scenes/`, plus these rules. Draw anything with HTML, SVG, CSS, rough.js, or KaTeX; to show a recording, set `engine: hyperframes` and add a `<video class="clip">` (docs/scenes.md). Animate only with `EV.from`, `EV.to`, `EV.fromTo`, `EV.set`, and the helpers, timed with `EV.at(beat, "word")`, where the word is in that beat's `say`. Keep content inside `.safe`: text blocks of 8 words or fewer, 2 or fewer on screen, one color per concept, and "2/4" when there are steps. Each scene agent writes only `scenes/<id>.html`, runs `make stills SLUG=<slug> FORMAT=<f> SCENE=<id>` (the frame before each next beat, linted, in seconds; never a full render), reads the contact sheet it prints, fixes up to 2 passes, and returns its status and `LINT` lines. Then run the full `make preview SLUG=<slug> FORMAT=<f>` once: it renders 3 pages at a time and splits long scenes. Run every `make` in the foreground with the longest timeout, and never end your turn to wait for a background command: a dashboard job ends when you stop, and its commands stop too. Spawn one reviewer sub-agent per contact sheet; each returns the frames that do not match their `show:`, or "all match". Fix what they report. At most 2 passes; done when:
   - [ ] zero `LINT` lines and zero JS errors
   - [ ] each frame shows what its `show:` says
   - [ ] zero frames look broken, empty, or cramped
   Summary: the 720p MP4 paths, the contact sheets, any unticked box, and the `VERDICT 1080p:` line. Then ask for the preview approval: it approves the final video and the plan.
3. **Optional: 1080p.** After the approval, give the verdict from the `VERDICT 1080p:` line (also in `make status`) and ask the user: "Render 1080p? Verdict: <verdict>." Recommend no when it says "not needed"; recommend yes only when it says "worth it for big screens" and the video goes to a projector, a TV, or a public upload. Run `make video SLUG=<slug> FORMAT=<f>` only on a yes. In a dashboard job (the request says "Dashboard job"), stop after the preview check: the page offers 1080p with the verdict. Summary: each MP4 path and length, plus the share check: zero customer data, zero secrets, audience internal or public.

Never edit `approved.json` or approve for the user. PRs, repos, HTML pages, and internal docs are confidential: put zero customer data or secrets in a video, and use fake example values. A page capture shows the page as it is, so delete or redraw a section that shows customer data, personal names, booking references, or links to private threads.
