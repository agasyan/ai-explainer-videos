---
name: explainer-video
description: Make a narrated, animated explainer video about any topic, PR, repo, doc, or recording, drawn as HTML/SVG animation code, as a 9:16 story and/or 16:9 landscape MP4, in parts when long. Writes the script and storyboard and stops for approval, renders a 720p preview and stops for approval, then renders 1080p. Use when the user asks for an explainer video, an animated explanation, a video about a PR or repo, a reel or story explainer, or to continue a video in generated_videos/.
argument-hint: "<topic | PR | repo path | file | slug> [--format story|landscape|both] [--moodboard <name>] [--video-format <name>] [--auto-until-preview] [--voice af_heart|am_michael|bf_emma|bm_george] [--length 60s]"
---

Two approval checks: the plan after step 1 and the 720p preview after step 2. Nothing heavy runs before the plan is approved; 1080p runs only after the preview is approved. For an existing slug, run `make status SLUG=<slug>` and continue from there. To ask: show the summary, then run `make approve SLUG=<slug> STEP=<plan|preview>`. Claude Code asks the user, and that answer is the approval. If the user declines, apply their change and ask again. If the command is denied without a message (headless run), stop and end with `WAITING FOR APPROVAL: <slug> <step>`. Editing an approved file cancels its approval; say what changed when you ask again.

Auto until preview: with `--auto-until-preview` (or "Auto until preview" in the request), run `make status SLUG=<slug>` right after `make new`. If the plan line shows `AUTO`, the user gave consent already (the dashboard does this). Else run `make auto SLUG=<slug>`: Claude Code asks the user, and that answer is the consent. With the consent, do not stop after step 1: go on to step 2, then ask for the preview approval, which approves the plan too. Without it, stop after step 1 as usual.

Defaults: `landscape` (`story` if the user says IG, reel, story, phone, or TikTok), moodboard and video format recommended (step 1), voice `af_heart`, captions `pop`, viewer a smart colleague new to the topic, 60 s per story part, 2 min per landscape part.

**Sub-agents, for speed.** At most 5 per step, all spawned in one message so they run in parallel; more items than 5 means 2 per agent. Sub-agents start blank, so paste in each one: the objective, input file paths, the rules it needs, its output shape, and a status of `DONE`, `DONE_WITH_CONCERNS`, or `BLOCKED` plus the reason. Sub-agents never run `make approve`, `make auto`, `make narrate`, or `make video`, and never edit `script.yaml`, `style.css`, or `approved.json`. The main agent keeps the script, the style, the approvals, and 1080p. Without sub-agents, do the same work yourself.

1. **Plan: script and storyboard.** Read the source. For 5 or more files or sections, spawn reader sub-agents, one per group; each returns 15 or fewer facts, each with `path:line` or its section. Write the script yourself, in one voice. Topic: research first, with up to 5 researcher sub-agents, one per question group. Each opens every source it cites, takes each number and date from the page, and returns rows `| c<n> | claim | source 1 | source 2 | status |`; a claim needs two independent sources, else its status is `one source`. Write the rows to `research.md`, and give each beat that states a fact `sources: [c<n>]`. Then spawn one recommender sub-agent. Paste in the brief, the `research.md` path, `moodboards/catalog.json`, `video-formats/catalog.json`, and this rule: return the best video format and the best moodboard for this topic and viewer, plus 2 alternatives each, each with one line of why tied to the topic; pick a moodboard with `three: true` only for a spatial topic. Write its answer as `picks:` in `script.yaml` (the pick first) and set `video_format:` and `moodboard:` to the picks. A choice in the request (`Video format: x`, `Moodboard: y`) skips that catalog: set the field and leave its picks list empty. Set `three:` from the request (`3D: off` means `three: false`; else `true`). PR: `gh pr view <n> --json title,body,files` and `gh pr diff <n>`; tell it as problem, change, effect, risk. Repo: README, a depth-2 tree, entry points, 3 core files; tell it as purpose, main parts, one request through it, how to start. File: all of it. Recording: `make transcribe FILE=<path>`. Reference video: `make reference FILE=<path>`, then match its words and cuts per minute. Run `make new SLUG=<kebab-slug> TITLE="<title>"` (when the request says `Slug: <slug>`, use exactly that slug, in every command), then replace every `(fill in)` in `script.yaml` and write each beat's `say` (narration) and `show` (what is on screen). Shape the scenes by the acts and beat ranges in `video-formats/<name>/format.md`, and give each scene a `treatment:` from `moodboards/<name>/moodboard.md`. A change request such as "use moodboard archival" sets the field, maps each treatment again, and runs narrate again. One beat is one visual change and 1 to 2 sentences. A story part is 60 s or less (140 words); a landscape part is 3 min or less (420 words); more means more parts, each opening with one sentence of context. Write `say` about 80% of the way to ASD-STE100: 20 words or fewer per sentence, active voice, one word per meaning. Sentence one is the payoff; the last beat is the win plus one next action. Spell out what the voice reads ("two percent", "A P I"); code and URLs go in `show` only. Wrap 1 to 2 key words per beat in `*asterisks*`; the captions color them. Run `make narrate SLUG=<slug>` and fix until it prints no `CHECK` (voice, sources, picks, treatments). State only facts you read; list guesses in `brief.guesses`. Summary: `storyboard.md` (the picks, the video direction, one row per beat), the length per part, and `build/narration.wav`.
2. **Preview: animation as code, 720p.** Write `style.css` yourself first: one color per concept and the shared classes, on top of the moodboard (scenes link `/ev/theme.css` after `base.css`, as the templates do). Then spawn one scene sub-agent per scene. Paste in each: its scene id, its `treatment`, and its beats (`id`, `say`, `show`), the path `moodboards/<name>/moodboard.md` (draw the treatment as its prose says), the paths `ev/web/ev.js` (API comment), `docs/scenes.md`, `style.css`, and `templates/video/scenes/`, plus these rules. Draw anything with HTML, SVG, CSS, rough.js, or KaTeX; to show a recording, set `engine: hyperframes` and add a `<video class="clip">` (docs/scenes.md). Animate only with `EV.from`, `EV.to`, `EV.fromTo`, `EV.set`, and the helpers, timed with `EV.at(beat, "word")`, where the word is in that beat's `say`. Keep content inside `.safe`: text blocks of 8 words or fewer, 2 or fewer on screen, one color per concept, and "2/4" when there are steps. Each scene agent writes only `scenes/<id>.html`, runs `make preview SLUG=<slug> FORMAT=<f> SCENE=<id>`, reads the contact sheet it prints, fixes up to 2 passes, and returns its status and `LINT` lines. Then run the full `make preview SLUG=<slug> FORMAT=<f>`; finished scenes come from the cache. Run every `make` in the foreground with the longest timeout, and never end your turn to wait for a background command: a dashboard job ends when you stop, and its commands stop too. Spawn one reviewer sub-agent per contact sheet; each returns the frames that do not match their `show:`, or "all match". Fix what they report. At most 2 passes; done when:
   - [ ] zero `LINT` lines and zero JS errors
   - [ ] each frame shows what its `show:` says
   - [ ] zero frames look broken, empty, or cramped
   Summary: the 720p MP4 paths, the contact sheets, and any unticked box.
3. **Final: 1080p.** In a dashboard job (the request says "Dashboard job"), stop after the preview check: the page renders 1080p. Else run `make video SLUG=<slug> FORMAT=<f>` and leave it running. Summary: each MP4 path and length, plus the share check: zero customer data, zero secrets, audience internal or public.

Never edit `approved.json` or approve for the user. PRs, repos, and internal docs are confidential: put zero customer data or secrets in a video, and use fake example values.
